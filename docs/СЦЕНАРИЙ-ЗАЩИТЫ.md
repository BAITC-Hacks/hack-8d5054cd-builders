# Практикум: защита за 5 минут

Главная мысль: **бизнес получает понятный путь улучшения задачи, а её готовность влияет на место в открытом каталоге**. Команды сами откликаются, бизнес сам решает, с кем работать.

В ТЗ обязательна демонстрация работающего MVP до 5 минут. Слайды помогают объяснить решение, но все переходы показываем в приложении.

## Перед выходом

1. Запустить приложение по README и открыть `http://127.0.0.1:8501`.
2. Использовать **одну вкладку** для всех ролей. В новой вкладке будет отдельная сессия с исходными данными.
3. Начать с чистой сессии без ранее опубликованных демонстрационных карточек. Бизнес: **Alem Retail**. Команда: **DataCraft**.
4. Открыть презентацию «Практикум-защита.pptx» и этот сценарий рядом. В PowerPoint есть заметки докладчика.
5. Для предсказуемого прогона выбрать в сайдбаре **Настройки помощника → Источник AI → Локальный сценарий**. Этот режим явно обозначен и разрешён кейсом. Если показываете внешний AI, заранее проверить подключение; не тратить время защиты на настройку ключей.
6. Подготовить текст ниже для копирования. Пройти сценарий один раз с таймером, затем открыть свежую сессию для защиты. Не открывать `.env` на проекторе.

## Живое демо: точные действия

### 1. Слабый черновик и вопросы — около 30 секунд

- Роль **Бизнес**, раздел **Новая задача**.
- Нажать **Попробовать на примере**, затем **Получить вопросы**.
- Показать **10 / 100**, минимум три вопроса и группировку вопросов. Сказать: «В примере ответы уже подготовлены для быстрой демонстрации, в обычном сценарии их заполняет бизнес».
- Нажать **Сформировать карточку**.
- Показать редактируемую карточку, **100 / 100** и прирост **+90 баллов**. Сказать: «Пока это предпросмотр. Публикация требует подтверждения человека».

### 2. Рейтинг и позиция — около 55 секунд

- В разделе **Результат и условия** временно очистить только поле **Какие материалы есть?**. Остальные ответы оставить.
- Нажать **Ctrl+Enter** или кликнуть вне поля и дождаться пересчёта: Streamlit фиксирует изменение после завершения ввода.
- Показать предпросмотр **80 / 100** и подсказку о данных. Сказать: «Допустим, данные ещё не согласованы».
- Нажать **Подтвердить и опубликовать**. Показать место новой карточки в каталоге.
- Нажать **К моим задачам и откликам**.
- У новой карточки открыть **Редактировать опубликованную карточку**.
- Вставить в **Какие материалы есть?** текст из блока «Данные» ниже.
- Нажать **Сохранить изменения и пересчитать рейтинг**.
- Показать **100 / 100**, новую позицию и сообщение об изменении. В чистой сессии с пятью стартовыми карточками ожидается переход **с 4-го на 2-е место**. Если в сессии уже есть другие задачи, ориентироваться на фактические позиции на экране.
- Сказать: «За конкретное подтверждённое дополнение бизнес получил 20 баллов, и задача поднялась в каталоге. Это основная геймификация кейса».

### 3. Отклик и выбор бизнеса — около 50 секунд

- Переключить роль на **Студенческая команда**, команда **DataCraft**, раздел **Каталог**.
- Найти **Удобное оформление онлайн-заказов**. Показать общий каталог и фильтры по теме и готовности.
- Открыть **Предложить решение**. Вставить идею, план, срок и ссылку из блока ниже. Нажать **Отправить отклик**.
- Переключить роль **Бизнес**, раздел **Мои задачи**.
- Открыть предложения новой карточки. Показать идею, план и срок DataCraft, затем нажать **Выбрать команду**. Сравнительная таблица появляется при двух и более откликах; в этом коротком прогоне достаточно одного.
- Сказать: «Бизнес может выбрать несколько команд или не выбрать ни одну. Автоматического назначения нет».

### 4. Фактический прогресс — около 50 секунд

- Роль **Студенческая команда**, **Мои проекты**.
- Показать, что выбор команды сам по себе не дал XP.
- В первом доступном этапе заполнить **Что сделано и как проверено** текстом из блока «Отчёт по первому этапу» ниже. Нажать **Отправить этап на проверку**.
- Показать ожидание проверки и прежний XP.
- Роль **Бизнес**, **Мои задачи**, новая карточка. В **Результаты команд** нажать **Подтвердить этап · +20 XP**.
- Роль **Студенческая команда**, **Мои проекты**. Показать **20 XP** и следующий этап.
- Вернуться к слайду 6.

Если время заканчивается, сначала завершить ручной выбор бизнеса. Полный обязательный сценарий важнее показа всех трёх этапов. Оставшиеся этапы можно открыть при вопросах жюри.

## Короткие ответы жюри

**Почему AI?** Он анализирует описание, находит пробелы, формулирует вопросы и собирает JSON-карточку. Система сохраняет проверяемое происхождение фактов из ввода пользователя.

**Как считаете рейтинг?** Чистая функция с весами 20/20/15/15/10/10/10. Учитываем заполненность, длину содержательного текста и заглушки. Это объяснимая эвристика полноты. Она не доказывает истинность текста и не заменяет проверку человеком.

**Можно ли накрутить баллы длинным текстом?** Семантическую полезность эвристика оценивает ограниченно. В MVP есть подсказки и ручное подтверждение; в пилоте потребуется проверка качества содержания по примерам и обратной связи бизнеса.

**Что происходит без API?** Приложение явно сообщает о локальном режиме и завершает сценарий без падения. Подготовленный пример разрешён кейсом. Промпт, JSON-схемы и валидация доступны в исходниках и документации.

**Кто выбирает команду?** Только бизнес. Можно выбрать одну, несколько или ни одной команды. Рейтинг не назначает исполнителя.

**Что даёт низкий рейтинг?** Карточка остаётся в каталоге, отклик доступен. Студенты видят, что задаче ещё нужны уточнения.

**За что XP командам?** За подтверждённые бизнесом этапы: план 20, прототип 40, результат 60. Повторный просмотр или повторное нажатие не начисляет XP заново.

**Где данные и авторизация?** В этом MVP данные одной вкладки живут в `st.session_state`. Постоянной БД и авторизации нет. Это ограничение демонстрационного объёма, а следующий шаг для реального пилота.

**Какие API поддерживаются?** Есть адаптеры OpenAI и NVIDIA, выбор провайдера и резервный локальный режим. Состояние подключения показываем в приложении. Не утверждать, что оба внешних сервиса сейчас доступны, без актуальной проверки.
