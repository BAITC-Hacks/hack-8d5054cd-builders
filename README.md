# HackAlem AI — Практикум бизнес-задач

Команда **Builders** · HackAlem AI / AI Sana · версия 0.2.

Рабочий Streamlit MVP: бизнес уточняет задачу с помощью AI, подтверждает карточку и публикует её; студенческие команды отправляют предложения, бизнес вручную выбирает одну, несколько или ни одной команды.

## Запуск и обновление

Python 3.11+. Если локальная `.venv` уже существует, достаточно последней команды:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe -m streamlit run app.py
```

При обновлении не заменяйте свой `.env`: в нём ключи. После перехода с версии 0.1 один раз остановите Streamlit через Ctrl+C и запустите снова. Дальше изменения кода обычно подхватываются Streamlit; настройки из `.env` можно перечитать кнопкой в сайдбаре.

**Данные живут в `st.session_state` одной сессии браузера.** Для сквозного демо переключайте роли в одной вкладке. Другая вкладка или другой браузер получает собственный набор данных; перезапуск/переподключение может сбросить внесённые изменения. Постоянное хранение и совместная работа разных устройств в этот MVP не входят.

## Как подключить кредиты OpenAI и NVIDIA

Кредитный бонус и API-ключ — разные вещи. Сначала активируйте бонус каждого провайдера на странице хакатона и выполните инструкции организаторов. Приложение не может определить баланс или активировать бонус по скриншоту.

1. **OpenAI:** откройте [API keys](https://platform.openai.com/api-keys), создайте новый секретный ключ и сохраните его локально. [Официальный quickstart](https://developers.openai.com/api/docs/quickstart).
2. **NVIDIA:** войдите в [NVIDIA Build](https://build.nvidia.com/nvidia/nemotron-3-super-120b-a12b), нажмите **Get API Key** и скопируйте ключ. [Официальная инструкция](https://docs.api.nvidia.com/nim/docs/api-quickstart).
3. Откройте `.env` в папке рядом с `app.py` и заполните только свои значения:

```dotenv
DEMO_MODE=false
AI_PROVIDER=auto
AI_TIMEOUT_SECONDS=20
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4o-mini
NVIDIA_API_KEY=
NVIDIA_MODEL=nvidia/nemotron-3-super-120b-a12b
```

4. В приложении выберите **AI и подключение → Перечитать .env → Проверить подключение**. Проверка отправляет короткий служебный запрос и расходует немного токенов. Баланс кредитов она не проверяет.

Ключи не вставляются в исходный код, GitHub, README или чат. `.env` и другие локальные env-файлы исключены через `.gitignore`. Приложение показывает только наличие ключа, имя модели и безопасное описание ошибки. Значения ключей и тексты запросов не логируются. Явно заданные переменные окружения процесса имеют приоритет над `.env`.

### Выбор провайдера

- **Авто:** OpenAI → при ошибке NVIDIA → локальная сборка.
- **OpenAI** или **NVIDIA:** запрос только к выбранному API; при ошибке локальная сборка.
- **Локальный сценарий:** сеть не используется, можно пройти весь путь без ключей.

`DEMO_MODE=true` выбирает локальный сценарий при старте. Переключатель в сайдбаре действует для текущей сессии. Один запрос ограничен таймаутом из `.env`, повторные попытки SDK отключены. В режиме авто может быть два последовательных запроса, по умолчанию до примерно 40 секунд ожидания. Ключи провайдеров отправляются только на фиксированные официальные адреса API.

OpenAI использует [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Для NVIDIA используется официальный [OpenAI-совместимый endpoint](https://docs.api.nvidia.com/nim/reference/nvidia-nemotron-3-super-120b-a12b-infer). Для его hosted API не предполагается поддержка `response_format`: JSON запрашивается промптом и строго проверяется в Python. У модели NVIDIA отключён thinking; доступность модели и качество русского ответа нужно проверить своим ключом.

## Что улучшено в версии 0.2

- Два AI-провайдера, явный выбор и автоматический резерв; причины перехода на локальный сценарий видны в приложении.
- AI выделяет факты из черновика и ответов. Каждое поле собирается из точных цитат, найденных в соответствующем исходном тексте. Неподтверждённая цитата, некорректный JSON, отказ или обрезанный ответ запускают резервный путь.
- Исходная полнота считается по извлечённым полям. В локальном режиме распознаются строки вида `Данные: …`; для свободного текста предварительная оценка может быть занижена и явно отмечена как таковая.
- Известные заглушки («Не указано.», «Уточним позже после встречи») и очевидный повторяющийся мусор не повышают рейтинг.
- При смене студенческой команды форма использует её имя. После отправки форма очищается, число откликов обновляется.
- Имя бизнеса сохраняется при переключении ролей; решения бизнеса и сохранённый рейтинг обновляются сразу.
- Неполные адреса прототипов вроде `https://` отклоняются.

Проверка точного совпадения цитат исключает добавление нового текста в AI-поля, но не гарантирует правильную классификацию фактов. Бизнес проверяет смысл, может исправить текст и подтверждает публикацию. Рейтинг оценивает заполненность, а не реальную ценность проекта или доказанность метрик.

## Архитектура

```text
app.py              Один Streamlit UI: роли, конструктор, каталог, решения
src/config.py       Настройки .env и переменных окружения
src/ai.py           OpenAI/NVIDIA, промпты, проверка источников, резерв
src/rating.py       Чистая функция рейтинга без AI
src/models.py       Карточка, отклик, профиль, проверка ссылки
data/seed.json      По 5 черновиков, карточек, профилей и откликов
tests/              Целевые проверки логики и сквозного сценария
```

Авторизации нет. Имя бизнеса выделяет «Мои задачи» внутри текущей сессии. Каталог открыт всем выбранным профилям команд в этой сессии и сортируется по рейтингу без фильтров. Низкий балл не блокирует отклик. Количество откликов и выбранных команд не ограничивается.

## Формула рейтинга

| Поле | Вес | Длина для полного веса |
|---|---:|---:|
| Контекст | 10 | 35 символов |
| Потребность | 10 | 20 символов |
| Данные и материалы | 20 | 15 символов |
| Ожидаемый результат | 15 | 20 символов |
| Критерии успеха | 15 | 20 символов |
| Ограничения | 10 | 14 символов |
| Пользователи | 10 | 10 символов |
| Контакт | 5 | 5 символов |
| Формат взаимодействия | 5 | 12 символов |
| **Итого** | **100** | |

Пустота, известная заглушка или явный мусор дают 0. Короткий ответ — половину веса с округлением вниз. Ответ от порога — полный вес. Повторные пробелы схлопываются. Это простая воспроизводимая эвристика заполненности; она не оценивает смысл с помощью AI. Название обязательно для публикации, в балл не входит.

Уровни: 0–39 — черновик, 40–69 — рабочая, 70–89 — готовая, 90–100 — приоритетная. До публикации отображается предварительный расчёт. После подтверждения карточки балл влияет на место в каталоге. Изменение опубликованной карточки сохраняется отдельной кнопкой с пересчётом рейтинга.

## Как это связано с критериями кейса

| Критерий | Что показать |
|---|---|
| Сквозной сценарий · 20 | Черновик → вопросы → публикация → отклик → выбор |
| Качество карточки · 15 | Все 10 полей, уместные вопросы, ручное редактирование |
| Геймификация бизнеса · 25 | Расшифровка баллов, подсказки, прирост, пересортировка каталога |
| Каталог и отклики · 15 | Низкий рейтинг доступен, любое число откликов, выбор вручную |
| AI-функция · 10 | Живой провайдер, источники фактов, обработка невалидного ответа |
| Техническое качество · 10 | Простой запуск, структура, валидация, автоматические проверки |
| Демонстрация · 5 | Один заранее подготовленный сценарий до 5 минут |

## AI вход и выход для защиты

Первый запрос получает `sources = {"draft": "текст бизнеса"}`. Второй добавляет `answer:context`, `answer:data` и другие ответы. Модель возвращает для каждого из 10 полей `field_sources` — список объектов `source` и `quote`. В первом ответе также есть `missing_fields` и не менее трёх `questions` с привязкой к полям.

Пример фрагмента ответа (остальные поля опущены только в этой иллюстрации):

```json
{
  "field_sources": {
    "data": [{"source": "answer:data", "quote": "Обезличенная выгрузка заказов за три месяца."}]
  }
}
```

Приложение проверяет структуру и наличие каждой цитаты в указанном источнике. Полные схемы, промпты и обработчики находятся в `src/ai.py`. При сбое второго запроса сохраняются уже проверенные сведения первого шага и явно введённые ответы бизнеса.

## Проверка и демо

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Автоматические проверки не используют настоящие ключи и не тратят кредиты: API заменён имитациями успешного ответа, таймаута, лимита и неправильного JSON. Реальное подключение проверяется кнопкой в приложении после добавления ключей.

Сценарий до 5 минут:

1. Выберите локальный сценарий или подключённый API. В роли бизнеса нажмите «Вставить пример для демо», затем «Проанализировать».
2. Покажите начальную полноту и вопросы. Предзаполненные демо-ответы — синтетические факты сценария, их можно изменить.
3. Сформируйте карточку. Покажите источники, редактируемые поля, баллы и подсказки; подтвердите публикацию.
4. В той же вкладке выберите студенческую команду, найдите карточку в каталоге и отправьте идею с планом.
5. Вернитесь к бизнесу, откройте «Мои задачи» и вручную выберите или отклоните отклик.

## Обновления через GitHub

Командный репозиторий: [BAITC-Hacks/hack-8d5054cd-builders](https://github.com/BAITC-Hacks/hack-8d5054cd-builders).

Когда рабочая папка связана с репозиторием, заменять её новой папкой не нужно. Изменения сохраняются коммитами, отправляются через `git push` и принимаются в основную ветку через pull request. На другом компьютере обновление получают через `git pull` и при необходимости заново устанавливают зависимости.

```powershell
git pull --ff-only
git add app.py src data tests README.md requirements.txt .env.example .gitignore
git commit -m "Improve task builder and AI integration"
git push
```

Коммит фиксирует версию локально; `push` отправляет её в GitHub. Публикация исходников в GitHub сама по себе не размещает Streamlit-приложение в интернете. `.env`, `.venv`, временные файлы и архивы в коммит не входят.
