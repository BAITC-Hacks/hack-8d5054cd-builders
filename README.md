# HackAlem AI — Практикум бизнес-задач

Проект **Builders** · HackAlem AI / AI Sana · финальная версия 0.5.

Рабочий Streamlit MVP: бизнес уточняет задачу с помощью AI, подтверждает карточку и публикует её; студенческие команды отправляют предложения, бизнес вручную выбирает одну, несколько или ни одной команды. Выбранные команды сдают этапы работы и получают XP после подтверждения результатов бизнесом.

## Запуск и обновление

Python 3.11+. Если локальная `.venv` уже существует, достаточно последней команды:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe -m streamlit run app.py
```

При обновлении не заменяйте свой `.env`: в нём ключи. Для новой темы один раз остановите Streamlit через Ctrl+C и запустите снова. Дальше изменения кода обычно подхватываются Streamlit; настройки из `.env` можно перечитать кнопкой в сайдбаре. Если в меню Streamlit ранее была вручную выбрана другая тема, переключитесь на тему приложения.

**Данные живут в `st.session_state` одной сессии браузера.** Для сквозного демо переключайте роли в одной вкладке. Другая вкладка или другой браузер получает собственный набор данных; перезапуск/переподключение может сбросить внесённые изменения. Постоянное хранение и совместная работа разных устройств в этот MVP не входят.

## Как подключить кредиты OpenAI и NVIDIA

Кредитный бонус и API-ключ — разные вещи. Сначала активируйте бонус каждого провайдера на странице хакатона и выполните инструкции организаторов. Приложение не может определить баланс или активировать бонус по скриншоту.

1. **OpenAI:** откройте [API keys](https://platform.openai.com/api-keys), создайте новый секретный ключ и сохраните его локально. [Официальный quickstart](https://developers.openai.com/api/docs/quickstart).
2. **NVIDIA:** войдите в [NVIDIA Build](https://build.nvidia.com/nvidia/nemotron-3-super-120b-a12b), нажмите **Get API Key** и скопируйте ключ. [Официальная инструкция](https://docs.api.nvidia.com/nim/docs/api-quickstart).
3. Откройте `.env` в папке рядом с `app.py` и заполните только свои значения:

```dotenv
DEMO_MODE=false
AI_PROVIDER=auto
AI_TIMEOUT_SECONDS=20
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4o-mini
NVIDIA_API_KEY=
NVIDIA_MODEL=nvidia/nemotron-3-super-120b-a12b
```

4. В приложении выберите **Настройки помощника → Перечитать .env → Проверить подключение**. Проверка отправляет короткий служебный запрос и расходует немного токенов. Баланс кредитов она не проверяет.

Ключи не вставляются в исходный код, GitHub, README или чат. `.env` и другие локальные env-файлы исключены через `.gitignore`. Приложение показывает только наличие ключа, имя модели и безопасное описание ошибки. Значения ключей и тексты запросов не логируются. Явно заданные переменные окружения процесса имеют приоритет над `.env`.

### Выбор провайдера

- **Авто:** OpenAI → при ошибке NVIDIA → локальная сборка.
- **OpenAI** или **NVIDIA:** запрос только к выбранному API; при ошибке локальная сборка.
- **Локальный сценарий:** сеть не используется, можно пройти весь путь без ключей.

`DEMO_MODE=true` выбирает локальный сценарий при старте. Переключатель в сайдбаре действует для текущей сессии. Один запрос ограничен таймаутом из `.env`, повторные попытки SDK отключены. В режиме авто может быть два последовательных запроса, по умолчанию до примерно 40 секунд ожидания. Ключи провайдеров отправляются только на фиксированные официальные адреса API.

OpenAI использует [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Для NVIDIA используется официальный [OpenAI-совместимый endpoint](https://docs.api.nvidia.com/nim/reference/nvidia-nemotron-3-super-120b-a12b-infer). Для его hosted API не предполагается поддержка `response_format`: JSON запрашивается промптом и строго проверяется в Python. У модели NVIDIA отключён thinking; доступность модели и качество русского ответа нужно проверить своим ключом.

## Интерфейс

- Светлая тема, мягкий фон и сдержанный зелёный акцент. Крупные поля, заметный фокус клавиатуры, статусы с текстовыми подписями.
- На каждой странице один главный заголовок и короткое объяснение следующего действия. Настройки помощника, правила и подробности открываются по необходимости.
- В конструкторе видны четыре шага. Вопросы и поля карточки разделены на три смысловые группы с примерами ответов. Предварительная готовность и подтверждение публикации находятся рядом с редактором.
- Карточки каталога показывают главное: результат, готовность, позицию и число предложений. Полное описание и форма отклика раскрываются отдельно.
- В «Моих задачах» предложения и результаты на проверке находятся перед редактированием. Задачи с ожидающими проверки этапами идут первыми.
- Опыт команды кратко показан в меню, подробные достижения — в «Моих проектах». У каждого этапа есть понятный статус, инструкция и следующее действие.

## Сквозной маршрут

- Конструктор показывает один шаг за раз: черновик → уточнение → проверка карточки и предварительного рейтинга → публикация. Черновик и ручные правки сохраняются при смене роли. Ответы в форме можно сохранить отдельной кнопкой.
- Повторный анализ того же текста сохраняет результат. Изменение черновика предупреждает о пересборке. После публикации появляется квитанция с баллом и местом в каталоге, а повторный запуск страницы не создаёт вторую задачу.
- Поля карточки сгруппированы по смыслу. Тему выбирает бизнес; она не влияет на рейтинг и не генерируется AI.
- Предпросмотр рейтинга явно отделён от подтверждённых баллов. Подсказки показывают прибавку и следующую цель готовности. Подтверждённое изменение карточки обновляет её место в общем каталоге.
- В каталоге есть фильтры по теме и готовности, кнопка сброса и глобальная позиция задачи. По умолчанию доступны все опубликованные задачи; низкий рейтинг не мешает откликнуться.
- Бизнес сравнивает идеи и планы в таблице, затем принимает решение по каждому отклику. Название команды связано с выбранным профилем.
- У студентов появились «Мои отклики» и «Мои проекты», у бизнеса — проверка результатов выбранных команд.

## Геймификация: «Маршрут до результата»

**Бизнес собирает паспорт готовности задачи.** Рейтинг 0–100, расшифровка и задания на уточнение помогают перейти через уровни 40 → 70 → 90. Баллы фиксируются после подтверждения карточки и определяют место в каталоге. Заполнение всех полей даёт 100, без дополнительных очков за клики или публикации.

**Команда проходит проект по трём этапам:**

| Этап | Что предъявить бизнесу | Награда после принятия |
|---|---|---:|
| План согласован | План, границы работы и признаки приёмки | 20 XP |
| Прототип проверен | Прототип и результаты проверки ключевого сценария | 40 XP |
| Результат принят | Итог и объяснение выполнения критериев успеха | 60 XP |

Всего за проект — **120 XP**. Команда отправляет описание сделанного и, при наличии, ссылку на результат. Бизнес видит отчёт рядом с критериями задачи и вручную подтверждает этап или возвращает его на доработку с обязательным комментарием. Прежние попытки и решения остаются в истории.

Новый этап открывается после принятия предыдущего. Отправка отчёта, отклик и сам выбор команды XP не дают. Награда начисляется один раз по сочетанию «задача + команда + этап»; несколько предложений одной команды не создают несколько маршрутов. У каждой выбранной команды свой прогресс. AI не принимает результаты и не начисляет XP.

Уровни опыта: 0 — «Старт», 20 — «Исследователь», 60 — «Создатель», 120 — «Практик», 300 — «Опытный практик». Достижения открываются за первый принятый план, прототип, завершённый проект и три завершённых проекта. XP и значки рассчитываются из подтверждённых этапов, отдельно от рейтинга бизнес-задачи. Смысловую оценку предъявленного результата делает бизнес; длина отчёта сама по себе не даёт баллов.

## Основа AI и надёжности из версии 0.2

- Два AI-провайдера, явный выбор и автоматический резерв; причины перехода на локальный сценарий видны в приложении.
- AI выделяет факты из черновика и ответов. Каждое поле собирается из точных цитат, найденных в соответствующем исходном тексте. Неподтверждённая цитата, некорректный JSON, отказ или обрезанный ответ запускают резервный путь.
- Исходная полнота считается по извлечённым полям. В локальном режиме распознаются строки вида `Данные: …`; для свободного текста предварительная оценка может быть занижена и явно отмечена как таковая.
- Известные заглушки («Не указано.», «Уточним позже после встречи») и очевидный повторяющийся мусор не повышают рейтинг.
- При смене студенческой команды форма использует её имя. После отправки форма очищается, число откликов обновляется.
- Имя бизнеса сохраняется при переключении ролей; решения бизнеса и сохранённый рейтинг обновляются сразу.
- Неполные адреса прототипов вроде `https://` отклоняются.

Проверка точного совпадения цитат исключает добавление нового текста в AI-поля, но не гарантирует правильную классификацию фактов. Бизнес проверяет смысл, может исправить текст и подтверждает публикацию. Рейтинг оценивает заполненность, а не реальную ценность проекта или доказанность метрик.

## Архитектура

```text
app.py              Один Streamlit UI: роли, конструктор, каталог, решения
src/config.py       Настройки .env и переменных окружения
src/ai.py           OpenAI/NVIDIA, промпты, проверка источников, резерв
src/rating.py       Чистая функция рейтинга без AI
src/catalog.py      Темы, фильтры и глобальный порядок каталога
src/progress.py     Этапы, подтверждения, XP и достижения
src/progress_ui.py  Представления проектов и проверки результатов
src/ui.py           Общие заголовки, шаги, статусы и стили
src/models.py       Карточка, отклик, профиль, проверка ссылки
.streamlit/config.toml Светлая тема приложения
data/seed.json      По 5 черновиков, карточек, профилей и откликов
tests/              Целевые проверки логики и сквозного сценария
```

Авторизации нет. Имя бизнеса выделяет «Мои задачи» внутри текущей сессии. Каталог открыт всем выбранным профилям команд в этой сессии и сортируется по рейтингу. Фильтры по теме и готовности включаются пользователем и сбрасываются одной кнопкой. При одинаковом рейтинге раньше опубликованная карточка идёт первой, затем сравнивается ID. Низкий балл не блокирует отклик. Количество откликов и выбранных команд не ограничивается. Проверки владельца и выбранной команды относятся к демонстрационной сессии, а не заменяют авторизацию.

## Формула рейтинга

| Поле | Вес | Длина для полного веса |
|---|---:|---:|
| Контекст | 10 | 35 символов |
| Потребность | 10 | 20 символов |
| Данные и материалы | 20 | 15 символов |
| Ожидаемый результат | 15 | 20 символов |
| Критерии успеха | 15 | 20 символов |
| Ограничения | 10 | 14 символов |
| Пользователи | 10 | 10 символов |
| Контакт | 5 | 5 символов |
| Формат взаимодействия | 5 | 12 символов |
| **Итого** | **100** | |

Пустота, известная заглушка или явный мусор дают 0. Короткий ответ — половину веса с округлением вниз. Ответ от порога — полный вес. Повторные пробелы схлопываются. Это простая воспроизводимая эвристика заполненности; она не оценивает смысл с помощью AI. Название обязательно для публикации, в балл не входит.

Уровни: 0–39 — черновик, 40–69 — рабочая, 70–89 — готовая, 90–100 — приоритетная. До публикации отображается предварительный расчёт. После подтверждения карточки балл влияет на место в каталоге. Изменение опубликованной карточки сохраняется отдельной кнопкой с пересчётом рейтинга.

## AI вход и выход для защиты

Первый запрос получает `sources = {"draft": "текст бизнеса"}`. Второй добавляет `answer:context`, `answer:data` и другие ответы. Модель возвращает для каждого из 10 полей `field_sources` — список объектов `source` и `quote`. В первом ответе также есть `missing_fields` и не менее трёх `questions` с привязкой к полям.

Пример фрагмента ответа (остальные поля опущены только в этой иллюстрации):

```json
{
  "field_sources": {
    "data": [{"source": "answer:data", "quote": "Обезличенная выгрузка заказов за три месяца."}]
  }
}
```

Приложение проверяет структуру и наличие каждой цитаты в указанном источнике. Полные схемы, промпты и обработчики находятся в `src/ai.py`. При сбое второго запроса сохраняются уже проверенные сведения первого шага и явно введённые ответы бизнеса.

## Проверка и демо

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Автоматические проверки не используют настоящие ключи и не тратят кредиты: API заменён имитациями успешного ответа, таймаута, лимита и неправильного JSON. Проверяются весь путь до 120 XP, возврат на доработку, защита от повторной награды, изоляция команд, фильтры, сохранение конструктора и отсутствие двойной публикации. Реальное подключение проверяется кнопкой в приложении после добавления ключей.

Сценарий до 5 минут:

1. Выберите локальный сценарий или подключённый API. В роли бизнеса откройте «Новая задача», нажмите «Попробовать на примере», затем «Получить вопросы».
2. Покажите начальную полноту и вопросы. Предзаполненные демо-ответы — синтетические факты сценария, их можно изменить.
3. Сформируйте карточку. Покажите источники, редактируемые поля, баллы и подсказки; подтвердите публикацию.
4. В той же вкладке выберите студенческую команду, найдите карточку в каталоге и отправьте идею, план, срок и при наличии ссылку на прототип.
5. Вернитесь к бизнесу, откройте «Мои задачи», сравните предложения и вручную выберите или отклоните отклик.
6. В роли выбранной команды откройте «Мои проекты». Отправьте описание согласованного плана и способа проверки; покажите, что XP пока не начислены.
7. В роли бизнеса откройте задачу, прочитайте отчёт и нажмите «Подтвердить этап · +20 XP» либо верните на доработку с комментарием.
8. Вернитесь к команде: 20 XP, первый значок и следующий этап. По той же схеме можно принять прототип и результат, получив 120 XP за весь проект.

## Обновления через GitHub

Командный репозиторий: [BAITC-Hacks/hack-8d5054cd-builders](https://github.com/BAITC-Hacks/hack-8d5054cd-builders).

Когда рабочая папка связана с репозиторием, заменять её новой папкой не нужно. Изменения сохраняются коммитами, отправляются через `git push` и принимаются в основную ветку через pull request. На другом компьютере обновление получают через `git pull` и при необходимости заново устанавливают зависимости.

```powershell
git pull --ff-only
git add app.py src data tests docs .streamlit README.md requirements.txt .env.example .gitignore
git commit -m "Improve task builder and AI integration"
git push
```

Коммит фиксирует версию локально; `push` отправляет её в GitHub. Публикация исходников в GitHub сама по себе не размещает Streamlit-приложение в интернете. `.env`, `.venv`, временные файлы и архивы в коммит не входят.
